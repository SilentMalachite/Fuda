## 1. 目的

ASD・ADHD・聴覚障害などがある人、作業記憶（ワーキングメモリ）に負担を感じやすい人が、**疲れずに・責められずに**「やること」「予定」「メモ」「流れ（カンバン）」を管理し、**決めた時刻に画面で知らせてもらえる**デスクトップアプリを作ります。スケジュール帳（手帳）としても使えます。

よくある TODO アプリ・カレンダー・メモアプリ・カンバンツールで困りやすい点:

- 機能と選択肢が多く、何をどこに入れるか毎回考えさせられる
- 音・赤いバッジ・「期限切れ」の表示で不安になる。音の通知には、聞こえないと気づけない
- 画面が勝手に動いたり、並びが勝手に変わったりする
- どこに何を置いたか、さっき何をしていたか、次の予定は何時かを覚えておく必要がある

fuda は **「カード」1種類だけ** を扱います。カードは **必ず5つの「場所」のどれか1か所** にあります。机の上の付箋や札と同じで、1枚のカードが2か所に置かれることはありません。

```
とりあえず ── 思いついたらまずここ（整理はあとで）
やること  ── チェックを付けて終わらせるもの
予定      ── 決まった日・時刻にあること（行く・会う・始まる）
メモ      ── 終わりのない書きとめ
ボード    ── 列（まだ／やっている／できた）に分けて進めるもの
```

「予定」の画面は **スケジュール帳** です。1日・1週間・1か月の見方で、予定と、日付のある「やること」「ボード」のカードを日付ごとに並べて見せます（§5.4）。カードの置き場所はそのままで、日付で **見るための** 画面です。

## 2. 設計原則

10個の原則です。画面や機能を作るときは、毎回このリストで確かめます（`CLAUDE.md` のチェックリストはこれを短くしたもの）。

### 原則1　一つの画面に、一つの目的
- 各画面の主な目的は1つ。主ボタン（いちばん目立つボタン）も1つ。
- 画面のいちばん上に、いまいる場所の名前を見出しとして出す（迷子にならないため）。

### 原則2　覚えなくていい
- **自動保存**。「保存」ボタンは作らない。
- アプリを閉じて開き直すと、**前と同じ画面・同じカード・同じウィンドウの大きさ**に戻る。
- 状態バーに「保存済み」と静かに出す（入力のたびに点滅させない。§6.5）。
- 次の知らせがいつかを、予定の画面とトレイにいつも出しておく（知らせが付いているかを覚えておかなくてよい）。
- ボタンには必ず文字を付ける。何をするボタンかを覚えさせない。

### 原則3　音に頼らない
- 音は既定で **オフ**。音を鳴らす設定にしても、必ず画面にも同じ内容を出す。
- 知らせは **知らせの窓**（§5.9）で出す。いつもほかの窓より手前に出て、**消すまで残る**。音が聞こえなくても気づける。
- 音声・動画を自動で再生しない。

### 原則4　勝手に動かない・変わらない
- ユーザーの操作なしに、並び順・レイアウト・スクロール位置を変えない。
- 並び順の決まりは「**新しいカードはいちばん上に入る**」と「**予定は時刻の順**」の2つだけ。あとは手で並べた順を守る。
- アニメーションは既定で **オフ**（設定「動きを減らす」が既定でオン）。オンにしても 150ms 以下、拡大・回転・揺れは使わない。
- チェックを付けたカードも、その場で取り消し線になるだけで、**画面を移るまで位置は動かない**（§5.3）。
- 知らせの窓は決まった隅に出て、**キーボードのフォーカスを奪わない**（ほかのアプリで入力中の文字が、知らせの窓に入ったり消えたりしない）。

### 原則5　時間で急かさない
- 自動で消えるメッセージを作らない。メッセージは次の操作をするか［閉じる］を押すまで残る。
- 時間制限のある操作を作らない。
- 秒単位のカウントダウンを出さない。残り時間は分単位（1時間以上は時間と分、翌日以降の予定は日付と時刻）で書く。

### 原則6　責めない
- 日付が過ぎたカードを **赤・警告マーク・「期限切れ」の言葉で出さない**。ふつうの色で「日付が過ぎたもの」と書くだけ。
- 未完了の数のバッジを出さない。
- 連続記録（ストリーク）、ポイント、達成率のグラフを作らない。
- 「あとで」（日付を明日に移す）と「10分後にもう一度」は、それぞれ1回の操作でできるようにする。

### 原則7　いつでも取り消せる
- 削除はゴミ箱へ移すだけ。ゴミ箱は自動では空にならない。
- データを変える操作はすべて「元に戻す」できる（Ctrl/⌘+Z と、状態バーの［元に戻す］ボタン）。
- 確認ダイアログは **「ゴミ箱を空にする」だけ**（取り消せない唯一の操作のため）。

### 原則8　選択肢を少なく
- よく使うものだけ最初に見せ、残りは「その他」の中に入れる。
- 設定を足す前に、よい既定値で済まないかを考える。
- 一度に見せる選択肢はなるべく5つまで（知らせの時刻の選び方など、§5.8）。

### 原則9　言葉はそのまま・短く・いつも同じ
- 比喩、専門のカタカナ語、略語を避ける。動詞で書く（「追加」より「カードを書く」）。
- 同じものは、どの画面でも同じ名前で呼ぶ（§3 用語集）。
- アイコンだけのボタンを作らない。状態バーの閉じるボタンも文字（［閉じる］）で出す。スペースが限られる行や列の操作メニューだけ、例外として「…」を使ってよいが、必ず `accessible-label`（例: 「○○のメニュー」）とツールチップを付ける。

### 原則10　刺激を抑える
- 色は彩度を低めに。透明・ぼかし・グラデーション・影の多用をしない。
- **1秒に3回を超える点滅は禁止**（WCAG 2.3.1）。点滅そのものを基本的に使わない。知らせの窓も点滅させない。
- 色だけで意味を伝えない（文字や位置でも伝える）。土日・祝日も文字で示す（§7.6）。
- 太字や強調色は、見出しと主ボタンだけに使う。

## 3. 用語集（画面に出る言葉）

画面の文字・メッセージ・ドキュメントでは、左の列の言葉だけを使います。右の「使わない言葉」は画面に出しません。

| 画面の言葉 | 意味 | コード上の名前 | 使わない言葉 |
|---|---|---|---|
| カード | 書いたもの1枚 | `Card` | アイテム、タスク、ノート、エントリ、札 |
| 場所 | カードが置かれているところ（5つ） | `Place` | カテゴリ、フォルダ |
| とりあえず | すぐ書いて置いておく場所 | `Place::Inbox` | 受信箱、インボックス |
| やること | チェックを付けて終わらせるカードの場所 | `Place::Tasks` | タスク、TODO |
| 予定 | 決まった日・時刻にあること。その場所と、スケジュール帳の画面 | `Place::Events` | イベント、スケジュール、アポ、カレンダー |
| メモ | 終わりのないカードの場所 | `Place::Notes` | ノート |
| ボード | 列に分けてカードを進める場所 | `Place::Board`, `Board` | カンバン（説明文で1回だけ「カンバン方式」と書くのは可） |
| 列 | ボードの縦の並び | `Column` | レーン、ステータス |
| ステップ | カードの中の小さな手順（持ち物・準備にも使う） | `Step` | サブタスク、チェックリスト |
| できた | 終わったこと | `done` | 完了、達成 |
| あとで | 日付を明日に移すこと | `postpone` | 延期、スヌーズ |
| 日付 | そのカードの日 | `date` | 期限、締め切り、デッドライン |
| 時刻 | 何時何分。予定では「はじめ」と「おわり」 | `start_time`, `end_time` | タイム |
| 終日 | 時刻を決めない予定 | （`start_time` が空） | オールデイ |
| どこで | 予定の場所の名前（病院の名前など） | `location` | ロケーション、会場 |
| 日付が過ぎたもの | 日付が今日より前で、できていないもの | `overdue` | 期限切れ、遅れ |
| 知らせ | 決めた時刻に画面に出すお知らせ | `Reminder` | リマインダー、リマインド、アラーム、アラート |
| 知らせの窓 | 知らせを出す小さな窓 | `NoticeWindow` | ポップアップ、ダイアログ |
| パソコンの通知 | OS の通知センター（Windows のアクションセンター、macOS の通知センター）に出すもの | `os_notification` | プッシュ通知 |
| 10分後にもう一度 | 同じ知らせを10分後にまた出すこと | `remind_again` | スヌーズ |
| わかった | 知らせを見たので消すこと | `acknowledge` | 確認、閉じる |
| 閉じているあいだの知らせ | fuda が動いていなかったあいだに時刻が来た知らせ | `missed` | 見逃した、未読 |
| 繰り返し | 毎週などの決まりでくり返す予定 | `Recurrence` | 定期、リピート |
| この回だけ休み | 繰り返しの1回だけをなくすこと | `skip` | 例外、スキップ |
| 祝日 | 国民の祝日・休日 | `holiday` | — |
| いまの1つ | 1枚だけを大きく出す画面 | `Focus` | フォーカスモード、集中モード |
| 固定 | メモをいちばん上に置いておくこと | `pinned` | ピン留め |
| しまう | 一覧から見えなくすること（消さない） | `archive` | アーカイブ |
| ゴミ箱 | 消したカードの置き場 | `trash` | 削除済み |
| 片付けたもの | 「しまったもの」と「ゴミ箱」を見る画面 | `Tidy` | — |
| 元に戻す／やり直す | 直前の操作を取り消す／取り消しをやめる | `undo` / `redo` | アンドゥ、リドゥ |
| 色 | カードの目印 | `CardColor` | ラベル、タグ |
| さがす | 文字でカードを探すこと | `search` | 検索、フィルタ |
| トレイ | Windows の通知領域、macOS のメニューバーの右側 | `tray` | システムトレイ、タスクトレイ |

## 4. 対象となる人と、困りごとへの対応

機能は診断名で分けません。**誰にとっても楽なことを既定にする**のが方針です。

| 特性 | 困りやすいこと | fuda の対応 |
|---|---|---|
| ADHD | 思いついたことをすぐ忘れる | 「とりあえず」に1行で入れられる。どの画面からでも Ctrl/⌘+N、トレイからも |
| ADHD | 予定や「やる時刻」を忘れる | 知らせ（§5.9）。消すまで残る知らせの窓 |
| ADHD | 一覧が長いと、どれから手を付けるか選べない | 「いまの1つ」で1枚だけ出す |
| ADHD | 時間の感覚がつかみにくい | 知らせに「あと30分」と残り時間を書く。見えるタイマー（P2） |
| ADHD | できていない山を見て落ち込む | 責めない表示（原則6）、「あとで」1回 |
| ASD | 予告のない変化・急な切り替えがつらい | 勝手に動かない（原則4）。知らせを「前の日」「1時間前」など3つまで付けて、前もって心の準備ができる |
| ASD | あいまいな言葉がわかりにくい | 用語集で言葉を固定（§3）。繰り返しは「次は 11月24日（火）」と具体的な日を見せる |
| ASD・感覚過敏 | まぶしさ・色・動き・音がつらい | 低刺激の配色、動き・音は既定オフ、知らせも点滅しない |
| 聴覚障害 | 音の知らせに気づけない | 知らせはすべて画面に出す（原則3）。いつも手前に出る知らせの窓 |
| 聴覚障害 | その場で文字を見せて伝えたい | 「大きく見せる」表示（P2。§5.13） |
| 作業記憶の負担 | さっき何をしていたか、保存したか、知らせを付けたかを忘れる | 再開時に同じ場所へ戻る、自動保存＋「保存済み」、次の知らせをいつも表示 |
| めまい・前庭症状、目の疲れ | 画面の動き・小さい文字がつらい | 動きは既定オフ、文字の大きさ4段階 |
| 手の動かしにくさ | ドラッグや細かいクリックが難しい | ドラッグしなくても全部できる、押せる場所は 44px 以上 |

## 5. 画面

### 5.1 全体の配置

```
┌───────────┬───────────────────────┬──────────────────┐
│ 左: 場所   │ 中央: 一覧              │ 右: カードの中身    │
│           │  見出し（場所の名前）     │ （カードを開いたとき）│
│ とりあえず  │  書く欄                 │                  │
│ やること    │  カードの一覧            │                  │
│ 予定       │                        │                  │
│ メモ       │                        │                  │
│ ボード      │                        │                  │
│ ───────── │                        │                  │
│ いまの1つ   │                        │                  │
│ さがす      │                        │                  │
│ 片付けたもの │                        │                  │
│ 設定       │                        │                  │
├───────────┴───────────────────────┴──────────────────┤
│ 下: 状態バー  「保存済み」 ／ メッセージ ［元に戻す］［閉じる］    │
└──────────────────────────────────────────────────────┘
```

- **左（サイドバー）**: 上の5つ（場所）を大きく、下の4つを小さめに。いまいる場所は背景色と左の太線で示す（色だけにしない）。
- **中央（一覧）**: いちばん上に見出し、その下に「書く欄」。
- **右（カードの中身）**: カードを開いたときだけ出る。一覧は見えたまま。どの場所でも同じ。
- **下（状態バー）**: 常に出ている。メッセージは1つだけ。§6.5。
- **狭いとき**（ウィンドウ幅が 1100 論理px 未満、または文字の大きさが「特大」以上）: 中央と右を同時に出さず、カードを開くと右が中央を置き換える。上に「← 一覧に戻る」を出す。
- ウィンドウの最小サイズ: 960 × 640 論理px。
- 知らせの窓（§5.9）は、このウィンドウとは別の小さな窓。

### 5.2 とりあえず　**必須**

- 書く欄: プレースホルダ「思いついたことを書く」。Enter で追加。追加後もカーソルは書く欄に残る（続けて書ける）。
- 追加したカードは一覧のいちばん上に入る。
- 各行: タイトルと4つのボタン「やることへ」「予定へ」「メモへ」「ボードへ」（サイドバーと同じ順）。押すとその場所へ移り、状態バーに「『○○』をやることへ移しました ［元に戻す］」。
  - 「予定へ」は日付が決まっていない予定として移す。状態バーは「『○○』を予定へ移しました。日付はカードを開いて決められます ［開く］［元に戻す］」。
  - 「ボードへ」は、ボードが1つなら最初の列へ。2つ以上なら、どのボードかを選ぶ小さな一覧を出す。
- 空のとき: 「ここは空です。思いついたことを上の欄に書けます。」
- サイドバーに件数は出さない（原則6。件数表示は P2 の設定で）。

### 5.3 やること　**必須**

- 書く欄: プレースホルダ「やることを書く」。右に日付の3択「なし／今日／明日」（既定: なし）。
- まとまり（順番は固定。見出し付き）:
  1. **今日** — 今日の日付のもの。その下に、小さな見出し「日付が過ぎたもの」で日付が今日より前のもの（ふつうの文字色）。
  2. **明日**
  3. **これから** — 明後日以降
  4. **日付なし**
  5. **できた** — 既定でたたんでおく。見出しに「できた（12）」のように数を出してよい（責める数ではないため）。
- 「今日」の見出しのすぐ下に、今日の予定があれば1行だけ: 「今日の予定: 10:00 歯医者 ほか1件 ［予定を見る］」。予定のカードそのものはここには並べない（場所が違うため）。
- 1行の中身: チェックボックス（大きい）／タイトル／日付（「今日」「明日」「11月25日（水）」）と時刻（あれば「14:00」）／ステップの進み「2/5」／知らせがあれば「知らせあり」／色の印。
- チェックを付けると: その場で取り消し線になり、**位置は動かない**。別の画面に移るか開き直したときに「できた」へ移る。（実装: 画面ごとに「この画面を開いてからチェックしたカード」の集合を持ち、画面を移るときに捨てる。）
- 追加したカードが見えない位置に入ったとき: 状態バーに「『○○』を『日付なし』に追加しました ［見る］」。［見る］を押すとそこまでスクロールし、その行を背景色で強調する（動きなし。次の操作で強調は消える）。
- 「あとで」: 行の「…」メニューとカードの中身から。日付を明日にする（時刻と知らせはそのまま）。
- 並べ替え: 同じまとまりの中だけ、ドラッグか「上へ／下へ」（メニュー・Ctrl/⌘+↑↓）で。
- アプリを開いたまま日付が変わった（0:00 をまたいだ）ときは、操作なしに並びを変えず、状態バーに「日付が変わりました。表示を新しくしますか？ ［新しくする］［閉じる］」と静かに出す（画面を切り替えたときも新しい日付で表示し直す）。

### 5.4 予定（スケジュール帳）　**必須**

**見方**: 「1日」「1週間」「1か月」の3つ。既定は「1週間」。最後に使った見方と、見ていた日を覚えておく。

**上の段**（どの見方でも同じ）:
- 見出し「予定」
- 見方の切り替え「1日／1週間／1か月」
- 移動のボタン（見方に合わせた文字）: 「← 前の週」「今日」「次の週 →」
- いま見ている期間: 「2026年11月16日（月）〜22日（日）」
- 次の知らせの1行: 「次の知らせ: 今日 9:30 歯医者（30分前）」。なければ「次の知らせはありません」。

**書く欄**: プレースホルダ「予定を書く」。右に「日付」（既定: 今日。押すと「今日／明日／日付を選ぶ」）と「時刻」（既定: 終日。押すと時刻の入力、§6.6）。Enter で追加。

**1週間**（既定）:
- 7日を **縦に1行ずつ** 並べる（週の始まりは設定どおり）。時間の目盛りの表（時間割のような表示）は作らない（情報が詰まって読みにくいため。P3 で検討）。
- 各行の左: 「19日（木）」。今日の行は太い左線と「今日」の文字。祝日は祝日名（§7.6）。
- 各行の右に、決まった順で:
  1. 終日の予定
  2. 時刻のある予定（はじめの時刻の順。同じ時刻なら作った順＝`created_at` 昇順、`id` 昇順）: 「10:00〜11:00　歯医者　・○○歯科」。知らせがあれば小さく「知らせ 30分前」、繰り返しなら小さく「毎週」。
  3. その日の日付を持つ「やること」と「ボード」のカード: 小さな見出し「やること」の下に。やることはチェックボックス付き（できた になったやること も取り消し線・控えめな文字色 `text-muted` でその場に残し、その日の記録として見返せるようにする）、ボードのカードは「ボード: まだ」のように列の名前を添える。
- どの行にも小さな「この日に書く」ボタン（いつも見えている。マウスを乗せたときだけ出す、はしない）。
- 時刻が過ぎた予定は控えめな文字色（text-muted）にする。消したり動かしたりはしない。アプリを開いたまま日付が変わった（0:00 をまたいだ）ときは、並びや見ている日を勝手に変えず、状態バーで「日付が変わりました。表示を新しくしますか？ ［新しくする］［閉じる］」と静かに案内する（位置が変わらない `text-muted` の色変化のみ静かに更新してよい）。
- いちばん下に「日付が決まっていない予定」のまとまり。

**1か月**:
- 7列の格子。各マス: 日にち（今日は太線と「今日」）、祝日名、最大3行（予定のタイトルを時刻の順に。やることとボードは「やること 2」と**その日の合計件数**を1行にまとめる＝責める未完了数バッジにはしない）。入りきらなければ「ほか 2件」。
- マスを押すと「1日」の見方でその日を開く。

**1日**:
- 1週間の1行を大きくしたもの。いちばん上に「この日に書く」欄。

**カードを押すと** 右にカードの中身（§5.8）。やること・ボードのカードも、そのカードの中身が開く（場所は変わらない）。

### 5.5 メモ　**必須**

- 書く欄: プレースホルダ「メモを書く」。
- 並べ方: **大きさのそろったカードを格子状に**並べる。高さが違うカードを詰め込む並べ方（いわゆる石垣・Masonry）は使わない（位置がそろわず探しにくいため）。
  - カードの幅は文字の大きさに合わせて決める（目安 15em）。列の数はウィンドウ幅から計算する。
  - カードに出すもの: タイトル（太字）／本文の最初の4行まで（それ以上は「…」）／ステップの進み／色の印。
- まとまり: 「固定」（固定したメモ）→「ほか」の順。見出し付き。
- 一覧表示への切り替えは P2。

### 5.6 ボード　**必須**

- いちばん上に、いまのボード名と切り替え（「ボード: わたしのボード ▼」）。メニューに「ボードを追加」「名前を変える」「ボードを消す」。
- 最初に1つ「わたしのボード」を作っておく。列は「まだ」「やっている」「できた」。「できた」は **できた列**（§8.5）。
- 列の見出し: 名前と件数。上限（WIP 上限）を決めた列で数が上限を超えたら、見出しの下に「上限の3枚を超えています」とふつうの色で出す。**止めはしない**。
  - 「やっている」列の上限は既定で 3。
- 各列の下に「カードを書く」欄。
- カードに出すもの: タイトル、ステップの進み、日付と時刻（あれば）、「知らせあり」、色の印。
- カードの移動:
  - ドラッグ＆ドロップ（Slint の `DragArea` / `DropArea`）。置かれる位置に線を出す（動きなし）。動かしているカードは薄くする。
  - **ドラッグしなくてもできる**こと: カードの「…」メニュー「移動」→ 列の一覧から選ぶ。キーボードは Ctrl/⌘+←→（隣の列へ）、Ctrl/⌘+↑↓（列の中の順番）。
- 列の「…」メニュー: 名前を変える／左へ／右へ／できた列にする／上限を決める／列を消す。
  - 列を消すと、中のカードは **いちばん左の列** へ移る（状態バーに［元に戻す］）。最後の1列は消せない（メニューに出さない）。
- 列は最後に「列を追加」で足す。

### 5.7 いまの1つ　**必須**（タイマーと「次の予定」の表示は P2）

- どのカードからでも「…」メニュー「いまの1つにする」で選ぶ。選べるのは「やること」と「ボード」のカード。いまの1つは **同時に1枚だけ**。
- まだ選んでいないとき: 「今日」のやることを上から5枚まで出し、それぞれに「これにする」ボタン。今日のものがなければ「やること の一覧から選べます」と案内だけ出す。
- 選んだあとの画面:
  - タイトルを大きく（基準の2倍）。本文は長ければたたむ。
  - ステップの一覧。まだできていない最初のステップに「次はこれ」と印を付ける。
  - ボタン: 「ステップができた」（次はこれ のステップにチェック）／「カードができた」／「いまの1つをやめる」。
  - 右のカードの中身パネルは出さない。サイドバーは出したまま（戻り方に迷わないため）。
- カードができたら「できました。」と静かに出し、「次の1つを選ぶ」ボタンを出す。紙吹雪などの演出はしない。
- カードが消された・しまわれた・別の場所に移されたら、いまの1つは自動で外れる（状態バーで知らせる）。

### 5.8 カードの中身（右のパネル）　**必須**

**欄の並び** はどの場所でも同じ順番です。その場所で使わない欄は出しません。

| 順 | 欄 | とりあえず | やること | 予定 | メモ | ボード |
|---|---|---|---|---|---|---|
| 1 | タイトル（1行） | ○ | ○ | ○ | ○ | ○ |
| 2 | いつ: 日付 | — | ○ | ○ | — | ○ |
| 2 | いつ: 時刻 | — | ○（1つ） | ○（はじめ・おわり／終日） | — | ○（1つ） |
| 2 | いつ: 繰り返し | — | — | ○ | — | — |
| 3 | どこで | — | — | ○ | — | — |
| 4 | 知らせ | — | ○ | ○ | — | ○ |
| 5 | 本文（複数行の文字だけ。書式なし） | ○ | ○ | ○ | ○ | ○ |
| 6 | ステップ | ○ | ○ | ○ | ○ | ○ |
| 7 | その他（既定でたたむ） | ○ | ○ | ○ | ○ | ○ |

**日付**: ボタン「今日」「明日」「来週の月曜」「日付を選ぶ」（Slint の `DatePickerPopup`）「なし」。

**時刻**: §6.6 の書き方で入力できる欄と、「時刻を選ぶ」（Slint の `TimePickerPopup`、24時間表示）。予定は「はじめ」「おわり」（おわりはなくてよい）と「終日」の切り替え。日付がないときは時刻の欄を出さない。

**繰り返し**（予定だけ）: 「なし／毎日／毎週／2週間ごと／毎月／毎年」から選ぶ。
- 毎週・2週間ごと: 曜日を選ぶ（複数可・最低1つ必須で最後の1つは外せない。既定はその予定の日付の曜日）。起点の日と選んだ曜日が一致しない場合は起点の日には出ず、起点の日以降で最初に一致する曜日から始まる。
- 毎月: 「毎月 19日」のように、その予定の日付の日にち。
- 毎年: 「毎年 11月19日」。
- 「終わりの日」: なし／日付を選ぶ（起点の日を「終わりの日」より後に変えた場合は「終わりの日」を自動で外し、状態バーで知らせる。元に戻せる）。
- 選んだら、すぐ下に **次の3回の日付** を出す: 「次は 11月24日（火）、12月1日（火）、12月8日（火）」。
- 繰り返しの予定を開くと、いちばん上に「繰り返しの予定です。変えると、すべての回が変わります。」と出す（ふつうの文字色）。
- 「この回だけ変える」は P2。

**どこで**（予定だけ）: 1行。プレースホルダ「どこで（なくてもよい）」。

**知らせ**:
- 付いている知らせを1行ずつ: 「30分前 ［外す］」。**1枚に3つまで**。3つあるときは「知らせを足す」を出さず、「知らせは3つまでです」と書く。
- 「知らせを足す」を押すと、選ぶものを出す（5つまで＋「時刻を決める」）:
  - 時刻があるとき: 「ちょうど」「10分前」「30分前」「1時間前」「前の日の 20:00」「時刻を決める」
  - 時刻がないとき（終日、日付だけのやること）: 「その日の 8:00」「前の日の 20:00」「時刻を決める」
  - 「8:00」「20:00」は設定で変えられる（§5.12）。
  - 「時刻を決める」: 「その日／前の日／2日前」と時刻を選ぶ。
- 日付がないとき: 「日付を決めると、知らせを付けられます」とだけ書く。
- 時刻を消すと、「○分前」の知らせは外れる（状態バーで知らせ、元に戻せる）。

**ステップ**: 「ステップを書く」欄（Enter で追加。**いちばん下に入る**。ステップは手順なので上からの順番を守る）、一覧（チェック／文字の編集／上へ・下へ／消す）。予定では持ち物や準備に使える。

**その他**（既定でたたむ。開いたかどうかは覚えておく）:
- 色（§7.3 の7つから）
- 固定（メモのときだけ）
- 場所を移す（とりあえず／やること／予定／メモ／ボード）
- いまの1つにする（やること・ボードのとき）
- この回だけ休み（繰り返しの予定を、ある回から開いたとき）
- この回から先をやめる（同上。この回より前の回は残る。最初の回＝起点の日に対して行った場合は残る回がないため、予定をゴミ箱へ移す。元に戻せる）
- 大きく見せる（P2）
- しまう
- ゴミ箱へ（繰り返しの予定では、すべての回がゴミ箱へ）
- 作った日・変えた日（表示だけ）

**保存**: 入力をやめて 300ms たったとき、別の欄に移ったとき、パネルを閉じたとき、アプリを閉じるときに保存する。入力欄にフォーカスが入った時点で元の値を覚えておき、300ms ごとに DB へ自動保存しつつ、元に戻す の履歴上は欄を出るまでを 1 単位としてまとめる（§6.4）。時刻の入力がまちがっているときは保存せず、欄の下に理由を出す（§6.6）。

**閉じる**: Esc か「閉じる」ボタン。

### 5.9 知らせ　**必須**（音と画面の端の光は P2）

**いつ出すか**
- 知らせの時刻になったら出す（30秒ごとに確かめるので、最大30秒ほど遅れることがある）。
- 知らせを出さないもの: できた になったやること・ボードのカード、しまった・ゴミ箱のカード、「この回だけ休み」の回。

**出し方**（2つを同時に）

1. **知らせの窓**（いつも出す。オフにはできない）
   - 画面の決まった隅（既定: 右上。設定で変えられる）に出る小さな窓。**いつもほかの窓より手前**に出る。
   - **表示先ディスプレイと作業領域**: メインのウィンドウが出ていればそのディスプレイ、閉じていたり最小化されていたりするときは主画面（プライマリディスプレイ）に出す。メニューバー・Dock・タスクバーを除いた作業領域の内側に 16px の余白を取って、設定した隅へ出す。
   - **幅と最大高さ**: 幅は文字の大きさに合わせ、作業領域の幅 − 32px 以下に収める。高さの上限は作業領域の高さの 60% まで（最低 1 件と下のボタン行は見える高さ、最大でも作業領域の高さ − 32px）とし、超えるときは知らせの一覧だけをスクロールさせ、いちばん下の［全部わかった］は下に固定する。
   - **キーボードのフォーカスを奪わない**。ほかのアプリで入力中でも、打った文字は知らせの窓に入らない。
   - 点滅・動き・音なし。知らせの窓の文字も、文字の大きさの設定に従う。
   - 知らせが2つ以上あるときは、1つの窓に縦に並べる（新しいものが上）。窓をいくつも開かない。
   - **メインウィンドウ側の「いま出ている知らせ」欄**: 知らせが出ているあいだは、メインのウィンドウのいちばん上にも同じ知らせと操作ボタン（［わかった］［10分後にもう一度］［開く］／複数時は［全部わかった］）を静かに出す（知らせがないときは出さない）。メインのウィンドウ側で操作すると、知らせの窓からも同じように消える。
   - 1つの知らせの中身:
     ```
     9:30 の知らせ
     歯医者
     10:00〜11:00（あと30分）・○○歯科
     ［わかった］ ［10分後にもう一度］ ［開く］
     ```
     - 時刻があるとき: 開始まで1時間未満は「あと30分」、1時間以上（当日内）は「あと2時間10分」、翌日以降の予定は「明日 10:00〜11:00」「11月21日（土）10:00〜11:00」のように日付と時刻を書く。予定の時刻を過ぎているときは「10:00〜11:00（はじまって10分たちました）」（1時間以上なら「はじまって1時間20分たちました」）。責める言葉は使わない。
     - 終日の予定・時刻なしの やること／ボード: 残り時間は出さず「今日・終日」「明日・終日」（やること／ボードなら「今日」「明日」「11月25日（水）」）と場所（あれば）を書く。
     - やることのとき: 3つめのボタンは［あとで（明日）］にし、［開く］は「…」の中へ。
   - 2つ以上あるときは、いちばん下に［全部わかった］。
   - 窓に「×」は付けない（「わかった」とどう違うか迷わせないため）。
   - 「わかった」: その回の知らせは終わり。
   - 「10分後にもう一度」: 10分後にまた出す。何回でもできる。
   - 「開く」: fuda のウィンドウを前に出してそのカードを開き、その知らせは「わかった」にする。
   - 表示中の同期: 知らせが出ているあいだに、メイン画面でそのカードを「できた」「しまった」「ゴミ箱へ」「この回だけ休み」「対象外の場所へ移す」にしたときは、知らせの窓とメインウィンドウ上部の欄からもすぐに消す。
   - 知らせの窓での操作は「元に戻す」の対象にしない（カードそのものは変わらないため）。

2. **パソコンの通知**（設定でオン／オフ。既定はオン）
   - タイトルと時刻だけを OS の通知センター（Windows のアクションセンター、macOS の通知センター）に出す。
   - OS の集中モードや「応答不可」では出ないことがある。**だから知らせの窓が主で、こちらは補助**。

**閉じているあいだの知らせ**
- fuda が動いていなかった・パソコンが眠っていたあいだに時刻が来た知らせは、次に fuda が動いたときに知らせの窓に出す。見出しは「閉じているあいだの知らせ」。
- 出すのは **過去24時間ぶん** まで。それより前のものは出さない（いっぺんに大量に出て驚かせないため）。

**うしろで動く**
- 知らせは **fuda が動いているあいだだけ** 出せる。そのため:
  - fuda のウィンドウを閉じても、fuda は終わらずにうしろで動き続ける（既定。設定「ウィンドウを閉じたら」で変えられる）。
  - トレイに fuda の印を出す（Slint の `SystemTrayIcon`）。トレイのメニュー: 「fuda を開く」「とりあえずに書く」「次の知らせ: 9:30 歯医者」（表示だけ）「fuda を終わる（知らせは出なくなります）」。
  - 設定「パソコンを起動したら fuda を動かす」（既定オフ）。
  - fuda がすでに動いているときに、もう一度 fuda を起動した場合は、二重に起動せず、すでに動いている fuda のウィンドウを手前に出す。
- **初めて知らせを付けたとき**、状態バーに一度だけ: 「知らせは fuda が動いているあいだに出ます。ウィンドウを閉じても、うしろで動き続けます。」［パソコンの起動時にも動かす］［閉じる］。

### 5.10 さがす　**必須**

- 書く欄に文字を入れると、入力をやめて 200ms 後に結果を出す。
- 探す範囲: タイトル・本文・どこで・ステップの文字。ゴミ箱は入れない。「しまったものも探す」チェックは既定オフ。
- 空白（全角・半角）で区切って複数語を入れると、すべてを含むカードを探す（AND で探す）。
- 文字のゆれを吸収する: 全角／半角、大文字／小文字、カタカナ／ひらがなを同じとみなす（§8.6）。
- 結果は場所ごとに見出しを付けて出す。押すと、**サイドバーの選択もその場所に変わって**から、カードの中身を開く（いまどこにいるかがわかるように）。

### 5.11 片付けたもの　**必須**

- 2つのまとまり: 「しまったもの」と「ゴミ箱」。
- しまったもの: 各行に「戻す」（もとの場所へ）。
- ゴミ箱: 各行に「戻す」。いちばん上に「ゴミ箱を空にする」。
  - 押すと確認ダイアログ: 「ゴミ箱の12枚を完全に消します。元に戻せません。」［消す］［やめる］。**最初のフォーカスは［やめる］**。
- ゴミ箱は自動では空にしない。

### 5.12 設定　**必須**

変えるとすぐに反映する（「適用」ボタンなし）。

| まとまり | 項目 | 選べるもの | 既定 |
|---|---|---|---|
| 見た目 | 文字の大きさ | 標準（16px）／大（18px）／特大（22px）／最大（26px） | 標準 |
| 見た目 | 配色 | やさしい／くらい／はっきり | やさしい |
| 見た目 | 動きを減らす | オン／オフ | オン |
| 日付と時刻 | 週の始まり | 月曜／日曜 | 月曜 |
| 知らせ | 知らせの窓を出す場所 | 右上／右下／左上／左下 | 右上 |
| 知らせ | パソコンの通知にも出す | オン／オフ | オン |
| 知らせ | 「その日の」知らせの時刻 | 時刻 | 8:00 |
| 知らせ | 「前の日の」知らせの時刻 | 時刻 | 20:00 |
| 知らせ | 音を鳴らす（P2） | オン／オフ | オフ |
| 知らせ | 画面の端を光らせる（P2。点滅しない） | オン／オフ | オフ |
| 動き方 | ウィンドウを閉じたら | うしろで動き続ける／fuda を終わる | うしろで動き続ける |
| 動き方 | パソコンを起動したら fuda を動かす | オン／オフ | オフ |
| データ | 保存場所を開く／書き出す／読み込む／バックアップ | §8.10, §8.11 | 毎日自動 |
| キーボード | ショートカットの一覧（表示だけ） | — | — |
| このアプリについて | 版、ライセンス、Slint の表示、祝日データの出典（§11） | — | — |

### 5.13 大きく見せる　**P2**

- カードの「…」メニュー「大きく見せる」で、そのカードのタイトルと本文だけを画面いっぱいの大きな文字で出す。筆談や、相手に画面を見せて伝えるときに使う。
- Esc か「戻る」で元の画面へ。

## 6. 操作の決まり

### 6.1 キーボード

Windows・Linux は Ctrl、macOS は ⌘。

| キー | すること |
|---|---|
| Ctrl/⌘+N | どの画面からでも「とりあえず」に書く小さな欄を出す（Enter で追加、Esc で閉じる。画面は移らない） |
| Ctrl/⌘+F | さがす |
| Ctrl/⌘+Z | 元に戻す |
| Ctrl/⌘+Shift+Z（Windows は Ctrl+Y も） | やり直す |
| Ctrl/⌘+1〜5 | とりあえず／やること／予定／メモ／ボード へ |
| Enter | 選んでいるカードを開く |
| Esc | 開いているものを閉じる・ひとつ戻る |
| Space | フォーカスのあるチェックボックスを切り替える |
| Ctrl/⌘+↑↓ | カードの順番を動かす |
| Ctrl/⌘+←→ | ボードで隣の列へ移す。予定の画面では前／次の期間へ |
| Ctrl/⌘+Shift+R | いま出ている知らせの欄へフォーカスを移す |

- **1文字だけのショートカットは作らない**（うっかり押して変わるのを防ぐ）。
- 文字の入力欄にフォーカスがあり、その欄の中で編集した内容があるあいだの `Ctrl/⌘+Z`／`Ctrl/⌘+Shift+Z`（Windows は `Ctrl+Y` も）は、その欄の文字編集だけを戻す／やり直す（アプリのほかの操作は戻さない）。
- 知らせの操作はキーボードだけで完結できるようにする。メインのウィンドウの上に出る「いま出ている知らせ」欄は通常の Tab 順（左のサイドバーより前）で選べ、`Ctrl/⌘+Shift+R` ですぐにフォーカスを移せる。知らせの窓は出るときに自分からはフォーカスを奪わないが、クリックや OS のウィンドウ切り替えでフォーカスを移した場合は、窓の中を Tab / Enter / Space で操作できる。
- ショートカットの一覧は「設定 > キーボード」に書いておく。

### 6.2 マウス・タッチパッド

- 押せる場所は 44 × 44 論理px 以上。
- 1回のクリックで開く（ダブルクリックは使わない）。
- 右クリックメニューは「…」メニューと同じ内容を出すだけ。右クリックやドラッグでしかできない操作を作らない（WCAG 2.5.7）。

### 6.3 フォーカス

- フォーカスの枠は太さ 3px、配色ごとの `focus` 色（§7.2）。
- Tab の順番は 左 → 中央（書く欄 → 一覧）→ 右。
- カードを消したら、フォーカスは次の行へ（なくならないようにする）。
- 画面を移ったら、フォーカスはその画面の書く欄へ。

### 6.4 元に戻す

- データを変える操作は1つずつ「元に戻す」の単位になる。最大 100 回分。アプリを閉じると履歴は消える（ゴミ箱は残る）。
- 文字の入力は、**1つの欄に入ってから出るまで**を1単位にする（1文字ずつ戻さない）。入力欄にフォーカスが入ったときの値を覚えておき、300ms ごとに DB へ自動保存するあいだは、同じ欄の連続変更を 1 つの操作（`before`＝入る前の値、`after`＝最新値）へまとめる。欄からフォーカスが外れたとき、または別のカードを開いたときにその 1 単位を履歴に積む。
- 知らせの追加・外す、繰り返しの変更、「この回だけ休み」も元に戻せる。
- 設定の変更と、知らせの窓での操作は、元に戻す の対象にしない。

### 6.5 メッセージ（状態バー）

- 画面の上に浮かぶ通知（トースト）は使わない。メッセージは **状態バーにだけ** 出す（知らせは別。§5.9）。
- 同時に出すのは1つだけ。新しいものが来たら置き換える。
- 次の操作をするか［閉じる］を押すまで残る。時間で消さない。
- 元に戻せる操作のあとは［元に戻す］ボタンを付ける。ボタンは2つまで。
- 「保存済み」は状態バーの右端に出しっぱなしにする。保存に1秒以上かかったときだけ「保存中…」にする（入力のたびに表示を変えない）。
- 失敗したとき: 「保存できませんでした。もう一度ためしてください。」のように、何が起きたかと、することを書く。詳しい理由は［くわしく］を押したときだけ出し、ログにも書く。

### 6.6 日付と時刻の入力

- **時刻** は24時間で扱う。次の書き方を受け付ける（全角・半角どちらでも。先に NFKC をかける）:
  - `10` → 10:00、`930` → 9:30、`1030` → 10:30、`10:30`、`10時`、`10時30分`、`10時半`
  - `午前9時` → 9:00、`午後3時` → 15:00、`午後3時半` → 15:30
  - 午前・午後の境界: `午前0時`＝`00:00`、`午前12時`＝`00:00`、`午後0時`＝`12:00`、`午後12時`＝`12:00`、`午後1時`〜`午後11時`＝`13:00`〜`23:00`。`午前13時`以上・`午後13時`以上は受け付けない。
  - 組み合わせと桁数: `午前9:30`、`午後3時30分`、`午前10` などは受け付ける。数字のみは 1〜2 桁（`0`〜`23` → `00:00`〜`23:00`、`24`以上は不可）、3 桁（`030` → `00:30`、`930` → `09:30`）、4 桁（`1030` → `10:30`）。
  - 区切り記号: コロン区切りの分は 2 桁必須（`9:5` は不可、`09:05` や `9時5分` は可）。区切りに使えるのは `:`（全角 `：` 含む）と `時`・`分`・`半` のみ（`.` や `-` は受け付けない）。
- 受け付けないもの（`25:00`、`10:75` など）は保存せず、欄の下に「時刻は 0:00〜23:59 で書いてください」と出す。前の値は残す。
- 予定の「おわり」が「はじめ」より前（同じも含む）のときは、保存せず「おわりの時刻が、はじめより前です」と出す。**勝手に直さない**。
- 日をまたぐ予定（22:00〜翌1:00）と、何日も続く予定（旅行など）は P2。
- **日付** はボタンと `DatePickerPopup` で選ぶ。日付を文字で打つ欄は作らない（MVP）。
- 画面に出す日付の書き方: 「今日」「明日」「昨日」、それ以外は「11月25日（水）」、今年でなければ「2027年1月5日（火）」。

## 7. 見た目

### 7.1 値はトークンにまとめる

色・余白・角の丸み・文字の大きさは、すべて `ui/theme.slint` の `global Theme` から取ります。`.slint` の中に数値や色を直接書きません。

- 余白: 4 / 8 / 12 / 16 / 24 / 32（論理px。文字の大きさを変えても余白は固定とし、最小ウィンドウ 960×640・最大文字 26px でも本文の幅を確保する）

### 7.4 文字（フォント）

- **BIZ UDPゴシック**（Regular と Bold）をアプリに同梱し、`default-font-family` にする。ユニバーサルデザインの書体で、どの OS でも同じ見え方になるため。ライセンスは SIL Open Font License 1.1 で、`GPL-3.0-only` のバイナリへ静的に埋め込む形（`.slint` の `import "...ttf"` による `include_bytes!`）は使わず、配布物に独立したファイル（`fonts/`）として同梱し、起動時に外部ファイルから読み込む（`fuda-app/src/fonts.rs` の薄いラッパー経由、§11）。
- 時刻の数字は桁がそろうようにする（等幅の数字が使えるかを Phase 0 で確認。使えなければ時刻の欄の幅を固定する）。
- アイコンは MVP では使わない（文字だけ）。P2 で使うときも必ず文字を添える。

### 7.5 動き

- 「動きを減らす」オン（既定）: アニメーションなし。
- オフ: 色の変化と出し入れだけ、150ms 以下。移動・拡大・回転・揺れは使わない。
- 自動スクロールはしない。例外は、ユーザーが［見る］などを押した結果として、その場所へ移るときだけ。

### 7.6 土日・祝日の表し方

- 日付の横に、いつも曜日を書く（「19日（木）」）。
- 祝日は祝日名を文字で書く（「23日（月）勤労感謝の日」）。振替休日・国民の休日も同じ。
- **土日・祝日を赤や青で塗り分けない**（赤を使わない原則と、色だけで伝えない原則のため）。文字で区別する。
- 祝日のデータがない年（§8.9）を見ているときは、1か月の見方の上に「この年の祝日はまだ入っていません」と書く。

## 8. データ

### 8.1 保存場所

- OS の標準のアプリデータの場所（`directories` クレートの `ProjectDirs`）。例: macOS `~/Library/Application Support/fuda/`、Windows `%APPDATA%\fuda\`。
- ファイル:
  - `fuda.sqlite3` — 本体
  - `fuda.lock` — 二重起動を防ぐロック（macOS / Linux ではローカル通信用の `fuda.ipc` も同じ場所に置く）
  - `backups/fuda-YYYY-MM-DD-HHMMSS.sqlite3` — 自動バックアップ・手動バックアップ・復元前バックアップ（新しい7つを残す）
  - `logs/` — ログ（P2。MVP は標準エラー出力）

### 8.2 接続の設定

接続を開いたら毎回:

```sql
PRAGMA journal_mode = WAL;
PRAGMA foreign_keys = ON;
PRAGMA synchronous = NORMAL;
PRAGMA busy_timeout = 3000;
```

### 8.3 スキーマ（`migrations/0001_init.sql`）

- 記録の時刻（作った・変えた・しまった・消した・できた）は UTC の Unix ミリ秒（`INTEGER`）。
- カードの日付・時刻・知らせの時刻は、**利用者の地域の時計どおりの文字列**: 日付 `'YYYY-MM-DD'`、時刻 `'HH:MM'`、日時 `'YYYY-MM-DD HH:MM'`（`TEXT`）。「10:00 に歯医者」は、どこにいても 10:00 のまま。

```sql
CREATE TABLE boards (
  id          INTEGER PRIMARY KEY,
  name        TEXT    NOT NULL,
  position    INTEGER NOT NULL,
  created_at  INTEGER NOT NULL,
  updated_at  INTEGER NOT NULL
);

CREATE TABLE columns (
  id              INTEGER PRIMARY KEY,
  board_id        INTEGER NOT NULL REFERENCES boards(id) ON DELETE CASCADE,
  name            TEXT    NOT NULL,
  position        INTEGER NOT NULL,
  wip_limit       INTEGER CHECK (wip_limit IS NULL OR wip_limit > 0),
  is_done_column  INTEGER NOT NULL DEFAULT 0 CHECK (is_done_column IN (0, 1)),
  created_at      INTEGER NOT NULL,
  updated_at      INTEGER NOT NULL
);
CREATE INDEX idx_columns_board ON columns(board_id, position);

CREATE TABLE cards (
  id           INTEGER PRIMARY KEY,
  place        TEXT    NOT NULL CHECK (place IN ('inbox', 'tasks', 'events', 'notes', 'board')),
  column_id    INTEGER REFERENCES columns(id) ON DELETE RESTRICT,
  position     INTEGER NOT NULL,
  title        TEXT    NOT NULL DEFAULT '',
  body         TEXT    NOT NULL DEFAULT '',
  date         TEXT    CHECK (date IS NULL OR (length(date) = 10 AND date(date) IS date)),
  start_time   TEXT    CHECK (start_time IS NULL OR (start_time GLOB '[0-2][0-9]:[0-5][0-9]' AND start_time < '24:00')),
  end_time     TEXT    CHECK (end_time IS NULL OR (end_time GLOB '[0-2][0-9]:[0-5][0-9]' AND end_time < '24:00')),
  location     TEXT    NOT NULL DEFAULT '',
  done_at      INTEGER,
  color        TEXT    NOT NULL DEFAULT 'none'
               CHECK (color IN ('none', 'sora', 'midori', 'suna', 'sakura', 'fuji', 'ishi')),
  pinned       INTEGER NOT NULL DEFAULT 0 CHECK (pinned IN (0, 1)),
  search_text  TEXT    NOT NULL DEFAULT '',
  created_at   INTEGER NOT NULL,
  updated_at   INTEGER NOT NULL,
  archived_at  INTEGER,
  deleted_at   INTEGER,
  -- 場所ごとの決まり（§8.5）
  CHECK ((place = 'board') = (column_id IS NOT NULL)),
  CHECK (place IN ('tasks', 'board') OR done_at IS NULL),
  CHECK (place = 'notes' OR pinned = 0),
  CHECK (place IN ('tasks', 'events', 'board') OR (date IS NULL AND start_time IS NULL)),
  CHECK (start_time IS NULL OR date IS NOT NULL),
  CHECK (end_time IS NULL OR (place = 'events' AND start_time IS NOT NULL AND end_time > start_time)),
  CHECK (place = 'events' OR location = ''),
  CHECK (archived_at IS NULL OR deleted_at IS NULL)
);
CREATE INDEX idx_cards_place  ON cards(place, deleted_at, archived_at, position);
CREATE INDEX idx_cards_column ON cards(column_id, position);
CREATE INDEX idx_cards_date   ON cards(date, start_time);

CREATE TABLE steps (
  id          INTEGER PRIMARY KEY,
  card_id     INTEGER NOT NULL REFERENCES cards(id) ON DELETE CASCADE,
  text        TEXT    NOT NULL,
  done_at     INTEGER,
  position    INTEGER NOT NULL,
  created_at  INTEGER NOT NULL,
  updated_at  INTEGER NOT NULL
);
CREATE INDEX idx_steps_card ON steps(card_id, position);

-- 予定の繰り返し（予定のカードだけ。1枚に1つ）
CREATE TABLE recurrences (
  card_id     INTEGER PRIMARY KEY REFERENCES cards(id) ON DELETE CASCADE,
  freq        TEXT    NOT NULL CHECK (freq IN ('daily', 'weekly', 'monthly', 'yearly')),
  interval    INTEGER NOT NULL DEFAULT 1 CHECK (interval IN (1, 2)),
  weekdays    TEXT    CHECK (
    weekdays IS NULL OR (
      weekdays GLOB '[1-7]*'
      AND weekdays GLOB '*[1-7]'
      AND weekdays NOT GLOB '*[^1-7,]*'
      AND weekdays NOT GLOB '*,,*'
      AND weekdays NOT GLOB '*[1-7][1-7]*'
    )
  ),  -- 例 '2,4'（1=月 … 7=日。昇順・重複なしは service で正規化）
  until_date  TEXT    CHECK (until_date IS NULL OR (length(until_date) = 10 AND date(until_date) IS until_date)),
  CHECK ((freq = 'weekly') = (weekdays IS NOT NULL)),
  CHECK (freq = 'weekly' OR interval = 1)
);

-- 「この回だけ休み」
CREATE TABLE recurrence_skips (
  card_id  INTEGER NOT NULL REFERENCES recurrences(card_id) ON DELETE CASCADE,
  date     TEXT    NOT NULL CHECK (length(date) = 10 AND date(date) IS date),
  PRIMARY KEY (card_id, date)
);

-- 知らせの決まり（1枚に3つまで。数は service で守る）
CREATE TABLE reminders (
  id              INTEGER PRIMARY KEY,
  card_id         INTEGER NOT NULL REFERENCES cards(id) ON DELETE CASCADE,
  kind            TEXT    NOT NULL CHECK (kind IN ('before_start', 'day_time')),
  minutes_before  INTEGER,   -- before_start: はじめの時刻の何分前か
  day_offset      INTEGER,   -- day_time: その日 0、前の日 -1、2日前 -2
  at_time         TEXT,      -- day_time: 'HH:MM'
  created_at      INTEGER NOT NULL,
  updated_at      INTEGER NOT NULL,
  CHECK (
    (kind = 'before_start' AND minutes_before BETWEEN 0 AND 1440
       AND day_offset IS NULL AND at_time IS NULL)
    OR
    (kind = 'day_time' AND minutes_before IS NULL AND day_offset BETWEEN -2 AND 0
       AND at_time GLOB '[0-2][0-9]:[0-5][0-9]' AND at_time < '24:00')
  )
);
CREATE INDEX idx_reminders_card ON reminders(card_id);
CREATE UNIQUE INDEX idx_reminders_unique_before_start
  ON reminders(card_id, minutes_before) WHERE kind = 'before_start';
CREATE UNIQUE INDEX idx_reminders_unique_day_time
  ON reminders(card_id, day_offset, at_time) WHERE kind = 'day_time';

-- 出した知らせの記録（回ごとに1行）
CREATE TABLE reminder_log (
  id               INTEGER PRIMARY KEY,
  reminder_id      INTEGER NOT NULL REFERENCES reminders(id) ON DELETE CASCADE,
  occurrence_date  TEXT    NOT NULL CHECK (length(occurrence_date) = 10 AND date(occurrence_date) IS occurrence_date),   -- どの回か（繰り返しでない予定は cards.date と同じ）
  fire_at          TEXT    NOT NULL CHECK (length(fire_at) = 16 AND strftime('%Y-%m-%d %H:%M', fire_at) IS fire_at AND substr(fire_at, 12, 5) < '24:00'),   -- 'YYYY-MM-DD HH:MM'
  state            TEXT    NOT NULL CHECK (state IN ('showing', 'again', 'done')),
  show_again_at    TEXT    CHECK (show_again_at IS NULL OR (length(show_again_at) = 16 AND strftime('%Y-%m-%d %H:%M', show_again_at) IS show_again_at AND substr(show_again_at, 12, 5) < '24:00')),   -- again のとき、次に出す日時
  updated_at       INTEGER NOT NULL,
  UNIQUE (reminder_id, occurrence_date),
  CHECK ((state = 'again') = (show_again_at IS NOT NULL))
);

CREATE TABLE settings (
  key    TEXT PRIMARY KEY,
  value  TEXT NOT NULL
);
```

- テーブルをまたぐ不変条件（`recurrences` は日付あり `events` のみ、`reminders` は日付あり `tasks`/`events`/`board` のみ、`before_start` は `start_time IS NOT NULL` のみ、`until_date >= cards.date` 等）は、`service.rs` および JSON 読み込み時の検査で必ず守る。
- 最初の起動で、ボード「わたしのボード」と列「まだ」「やっている（上限3）」「できた（できた列）」を作る（これはマイグレーションではなく、core の初期化処理で行う）。
- マイグレーションは `include_str!` で埋め込み、`PRAGMA user_version` で番号を管理する。1つのマイグレーション = 1つのトランザクション。**過去のファイルは書き換えない**。

### 8.5 守るべき決まり（不変条件）

core の service 層で必ず守り、テストを書きます（一部は §8.3 の CHECK でも守る）。

1. カードはいつも1つの場所にある。`place = 'board'` のときだけ `column_id` がある。
2. `done_at` を持てるのは「やること」と「ボード」だけ。ボードでは **できた列にある ⇔ `done_at` がある**。
3. 場所を移すときの `done_at`:
   - やること → ボード: できていれば **できた列**、できていなければ **いちばん左の列** へ。
   - ボード → やること: できた列にあれば できた のまま、ほかは できていない。
   - 予定・メモ・とりあえず へ移すと `done_at` は消える（元に戻す で戻る）。
   - ボードの中でできた列へ移すと `done_at` を付け、できた列から出すと消す。
4. 日付・時刻・どこで・知らせ・繰り返しを持てる場所（**見えない値を残さない**。移すときに消し、元に戻す で戻す）:
   - 日付・時刻（はじめ）・知らせ: やること・予定・ボード
   - おわりの時刻・どこで・繰り返し: 予定だけ
   - とりあえず・メモへ移すと、日付・時刻・知らせ・どこで・繰り返しは消える。
5. 知らせは1枚に3つまで。同じカードへの同じ条件の知らせ（DB の部分ユニーク制約）および同じ回に同じ `fire_at` になる知らせの重複登録を禁止する。`before_start` の知らせは、はじめの時刻があるときだけ持てる。時刻を消すと `before_start` の知らせは外れる。
6. 繰り返しを持てるのは、日付のある予定だけ。日付を消すと繰り返しも外れる。`until_date` は `cards.date` 以上とし、`cards.date` を `until_date` より後に変えたときは `until_date` を外す。`weekly` の `weekdays` は 1〜7 の昇順・重複なしで最低 1 つ必須とする。
7. 知らせの記録（`reminder_log`）の更新と片付け:
   - 日付・時刻・繰り返しを変えたとき: そのカードの `reminder_log` のうち、`occurrence_date` が今日以降の行、および過去の `state IN ('showing', 'again')` の行を消す（新しい時刻で出直し、かつ過去分の残りを防ぐ）。
   - 知らせを新しく足しただけのとき: すでに付いている別の知らせの `reminder_log` は消さない（既に出た知らせの二度出しを防ぐ）。
   - カードを できた・しまった・ゴミ箱へ・この回だけ休み・対象外の場所へ移したとき: 該当する `state IN ('showing', 'again')` の `reminder_log` 行を片付け、表示中の知らせの窓とメインウィンドウ上部の欄からもすぐに消す。
8. 新しいカードの `position` は、同じ入れ物（とりあえず／やること／予定／メモ のそれぞれ、またはボードの列）の最小値 − 1（＝いちばん上）。ステップだけは最大値 + 1（いちばん下）。予定の画面は時刻の順に並べ、同じ時刻のときは作った順（`created_at ASC, id ASC`）で並べる（予定では `position` を並び順に用いない）。
9. 並べ替えは、その入れ物の `position` を 0, 1, 2… と重複なく振り直す（1つのトランザクションで）。「やること」のまとまり内で並べ替えた場合も、`place = 'tasks'` 全体を通して一意な `position` を振り直し、日付をまたいでまとまりが移っても順序が衝突しないようにする。
10. `deleted_at` があるカードはゴミ箱にだけ出る。`archived_at` があるカードは「しまったもの」にだけ出る。しまったカードをゴミ箱へ入れると `archived_at` は消す。
11. `pinned` はメモだけ。メモ以外へ移すと `pinned = 0`。
12. 列を消すとき、中のカードはいちばん左の列へ移す（ほかに列がなければ消せない）。ボードを消すとき、そのボードのカードは「やること」へ移す（できた列のものは できた のまま）。
13. `focus.card_id` のカードが、消された・しまわれた・できた になった・やること/ボード以外へ移ったら、`focus.card_id` を消す。自動で外れた場合は、直前の `focus.card_id` も同じ `Command` に記録し、「元に戻す」で復元する。
14. `search_text` は、タイトル・本文・どこで・ステップの文字のどれかが変わったら作り直す（§8.6）。

### 8.6 さがす ための文字の正規化

- `search_text = normalize(title + "\n" + body + "\n" + location + "\n" + 各ステップの文字)`
- `normalize`: Unicode NFKC → 小文字 → カタカナをひらがなに（U+30A1〜U+30F6 を −0x60）。
- 探すときは、探す文字に `normalize` をかけたあと、空白で分割し、空でないすべての語を `search_text LIKE '%' || ? || '%' ESCAPE '\'` の AND 条件で探す（`%` `_` `\` はエスケープする）。
- 数千枚なら LIKE で十分速い。5,000枚で 100ms を超えたら FTS5（trigram）を検討し、PROGRESS.md に記録する。

### 8.7 繰り返しの計算（`schedule.rs`）

回（その予定が起きる日）は **保存せず、見る期間のぶんだけ計算** します。

- **起点** = `cards.date`。起点より前に回はない。
- `daily`: 起点から毎日。
- `weekly`: 起点の週（月曜はじまりの ISO 週）を基準に `interval` 週ごと、`weekdays` の曜日（1〜7 昇順・重複なしで最低 1 つ必須）。起点より前の曜日は、最初の週には出さない。
  - 例: 起点 2026-11-18（水）、毎週 火・木 → 11/19（木）、11/24（火）、11/26（木）…
  - 例: 起点 2026-11-17（火）、2週間ごと 火 → 11/17、12/1、12/15 …
- `monthly`: 毎月、起点と同じ日にち。その月にその日がなければ **月末**（31日 → 30日・28日など）。
- `yearly`: 毎年、起点と同じ月日。2月29日は、うるう年でない年は 2月28日。
- `until_date`: その日を含めて終わり（`cards.date` を `until_date` より後に変えたときは `until_date` を外す）。
- `recurrence_skips` にある日は回にしない。
- 「この回から先をやめる」: `until_date` を、その回の前の日にする。ただし起点の日（最初の回）に対して行った場合は残る回が 0 回になるため、`until_date` は設定せずカード自体をゴミ箱へ移す（元に戻せる）。
- 祝日でも回は休まない（「祝日は休み」は P2）。

### 8.8 知らせの計算（`reminder.rs`）

- **知らせの日時**（`fire_at`）:
  - `before_start`: （回の日付 ＋ はじめの時刻）− `minutes_before`
  - `day_time`: （回の日付 ＋ `day_offset` 日）の `at_time`
- **出すかどうか**（起動直後の初回、30秒ごとの定期確認、パソコンが眠りから覚めたとき）:
  1. 次の 2 経路の和集合から候補を集める:
     - (a) いまから **24時間前〜いま** に `fire_at` がある知らせ（繰り返しの予定は、回の日付が「今日 −1日 〜 今日 +3日」の回について計算し、2日前の知らせ・最大1440分前を含める）。
     - (b) `reminder_log` に `state = 'showing'`、または `state = 'again'` かつ `show_again_at <= いま` が存在する行（元の `fire_at` が 24時間より前でも必ず拾い、「10分後にもう一度」の消失を防ぐ）。
  2. 出さないもの: `reminder_log` が `done` の回、`again` でまだ `show_again_at` が来ていない回、§5.9 で出さないとしたカード（カードが `done` / `archived` / `deleted` / `skip` / 対象外場所になっていれば出さず、該当する `showing` / `again` 行は片付ける）。
  3. 残ったものを知らせの窓およびメインウィンドウ上部の欄に出し、`reminder_log` を `showing` にする。
- **わかった** → `done`。**10分後にもう一度** → `again`、`show_again_at` = いま＋10分。**開く** → `done`。
- アプリを開き直したとき、`showing` の知らせはもう一度出す（消すまで残る）。
- **閉じているあいだの知らせ** の見出し判定（`last_checked_at` で管理）:
  - 起動直後の初回確認で `fire_at < 起動時刻`（分単位比較）かつ未記録のもの、または定期確認で `いま - last_checked_at > 2分`（パソコンが眠っていたと判定）かつ `fire_at <= いま - 2分` で未記録のものを「閉じているあいだの知らせ」として出す。その後 `last_checked_at = いま` を更新する。
- 時計は `Clock` から取る（テストで差し替える）。

### 8.9 祝日（`holidays.rs`）

- 内閣府の「国民の祝日」の CSV（`https://www8.cao.go.jp/chosei/shukujitsu/syukujitsu.csv`、文字コードは Shift_JIS 系）を、UTF-8 の `data/holidays_jp.csv`（`YYYY-MM-DD,名前`）に直してリポジトリに入れ、`include_str!` で埋め込む。**アプリはネットワークを使わない**。
- 直す作業は `tools/` の小さなスクリプトで行い、手順を README に書く。**毎年1回**（内閣府が翌年分を出したあと）更新する。
- 表にない年は祝日なし として扱い、§7.6 の注意を出す。「このアプリについて」に「祝日の表: 1955年〜2027年」のように入っている年を出す。
- 出典の表示は §11.2。

### 8.10 バックアップ

- ファイル名は `backups/fuda-YYYY-MM-DD-HHMMSS.sqlite3`（同秒に重なった場合は `-1`, `-2` … を末尾に付ける）とし、必ず `VACUUM INTO ?1` のパラメータバインドで作る（SQL 文字列の結合は禁止）。
- 起動時に `backup.last_date` が今日より前なら自動バックアップを行い、`backup.last_date` を更新する。
- 新しい7つを残し、古いものを消す（アプリが作ったバックアップのファイルだけを対象にする）。
- 設定画面から「いまバックアップする」「バックアップから戻す」を行える。「バックアップから戻す」は確認ダイアログを出さず設定画面内の **2 段階のインライン操作**（対象行の［この時点に戻す］→ 行内に説明と［戻す］［やめる］を展開）とする。
- 復元の安全手順: (1) 選んだバックアップファイルを検査接続で開き `PRAGMA quick_check`・`user_version`・必須テーブルを確かめる、(2) いまの DB を復元前バックアップとして保存する、(3) いまの DB 接続を完全に閉じる、(4) 既存の `fuda.sqlite3-wal` と `fuda.sqlite3-shm` を消す、(5) 一時ファイル経由で `fuda.sqlite3` を置き換えて再接続し、元に戻す履歴を空にする。

### 8.11 書き出し・読み込み

- **書き出し（JSON）**: すべてのボード・列・カード・ステップ・繰り返し・知らせ（`reminder_log` は入れない）。

  ```json
  {
    "format": "fuda-export",
    "version": 1,
    "exported_at": "2026-11-19T10:00:00Z",
    "boards": [], "columns": [], "cards": [], "steps": [],
    "recurrences": [], "recurrence_skips": [], "reminders": []
  }
  ```
- **書き出し（Markdown）**: 場所ごとに1ファイル。読むためのもの（読み込みはしない）。
- **読み込み（JSON）**: 自分の書き出した形式だけ。いまのデータに「足す」（ID は振り直す）。読み込む前に自動でバックアップする。
- 予定の iCalendar（.ics）書き出し・読み込み、Google Keep の書き出し（Takeout）の読み込みは P3。

### 9.2 データの流れ（一方通行）

```
ユーザーの操作
  → Slint のコールバック（global Bridge）
  → bridge.rs
  → fuda-core の service（1操作 = 1トランザクション）→ Command を返す
  → history.rs に Command を積む
  → views/ が「いまの画面」のモデルを DB から作り直す
  → Slint が表示し直す
```

- **DB がただ一つの正しいデータ**。Slint のモデルは、表示のための使い捨ての写しです。
- 一覧は、変更のたびに **今の画面のぶんだけ** 作り直します。部分的な更新の工夫は、遅いと測れたときだけ考えます。
- MVP では、すべてメインスレッドで行います。1つの操作が 50ms を超えると測れたら（tracing のスパンで測る）、DB 用のスレッドを分けることを考え、PROGRESS.md に記録します。

### 9.3 元に戻す のしくみ

- service の関数は、変更の前後の状態を持つ `Command` を返します（例: `MoveCard { card_id, before: CardSnapshot, after: CardSnapshot }`。場所を移すと日付や知らせが消えることがあるので、知らせ・繰り返しも含めた写しを持ち、また `focus.card_id` が自動で外れる操作では外れる前の `focus.card_id` も含めて復元できるようにします）。
- `history.rs` は「元に戻す」と「やり直す」の2つの積み重ねを持ちます（最大 100）。新しい操作をしたら「やり直す」は空にします。
- ゴミ箱へ入れる操作も Command です（`deleted_at` を付ける／消す）。

### 9.4 Slint とのやりとり

- `.slint` には表示のための状態だけを置きます。並べ方、日付の判定、繰り返しの計算、移動のルールは core に書きます。
- Rust とのやりとりは `ui/bridge.slint` の `export global Bridge` にまとめます。例:

  ```slint
  export enum PlaceKind { inbox, tasks, events, notes, board }

  export struct CardRow {
      id: int,
      title: string,
      when-text: string,     // 「今日 14:00」「10:00〜11:00」など。core で作る
      is-overdue: bool,      // 「日付が過ぎたもの」の見出しに入れるため。赤くはしない
      is-past: bool,         // 予定の時刻が過ぎた（控えめな文字色にする）
      done: bool,
      steps-text: string,    // 「2/5」
      has-reminder: bool,
      repeat-text: string,   // 「毎週」など。なければ ""
      color: string,         // "sora" など
      highlighted: bool,
  }

  export global Bridge {
      in property <PlaceKind> current-place;
      in property <[CardRow]> rows;
      in property <string> next-reminder-text;   // 「次の知らせ: 今日 9:30 歯医者（30分前）」
      in property <string> status-message;
      in property <bool> status-can-undo;
      callback add-card(PlaceKind, string /* title */, string /* date */, string /* time */);
      callback toggle-done(int /* card id */);
      callback open-card(int);
      callback move-to(int /* card id */, PlaceKind);
      callback undo();
  }
  ```
- Slint の `int` は 32bit です。カードの ID（SQLite の 64bit）は、変換のときに範囲を確かめます（`i32::try_from`）。
- 画面の文字はすべて `@tr("...")` で書きます（日本語のまま）。英語は P3 で Slint の翻訳の同梱機能を使って足します。
- 操作できる要素には `accessible-role` と `accessible-label` を付けます。

### 9.5 知らせのしくみ

- `notifier.rs` が `slint::Timer` で 30 秒ごとに `reminder::due(&conn, &clock)` を呼び、出すものがあれば `notice.rs` が知らせの窓を出す・中身を更新する。
- 知らせの窓は2つ目の Slint の窓（`ui/notice.slint` の `NoticeWindow`）。`always-on-top` を使う。**出すときにフォーカスを奪わない**方法を Phase 0 で確かめる（できない OS があれば、その OS での代わりの方法を spike-report に書く）。
- 知らせの窓の配置は `slint::winit_030` と OS API で対象ディスプレイ（メインウィンドウ表示中はそのディスプレイ、非表示・最小化時はプライマリディスプレイ）の作業領域を取得して決める。最大高さ（作業領域の 60%、かつ作業領域の高さ − 32px 以下）を超えるときは一覧をスクロールし、［全部わかった］を下端に固定する。また、メインのウィンドウ上部の「いま出ている知らせ」欄と状態を同期する。
- パソコンの通知は `os_notify.rs`（候補: `notify-rust`）。失敗しても知らせの窓は必ず出す（エラーはログだけ）。
- メインのウィンドウを閉じても、トレイ（`ui/tray.slint` の `SystemTrayIcon`）があるあいだはイベントループを続ける（例: `slint::run_event_loop_until_quit()`。Phase 0 で確認）。
- 二重起動の防止（`single_instance.rs`）: DB を開く前にデータ保存場所の `fuda.lock` を OS の排他ロック（`std::fs::File::try_lock`）で確保する。すでに動いている場合は、ネットワークソケットを使わずローカル IPC（macOS / Linux は Unix ドメインソケット `fuda.ipc`、Windows は Named Pipe 等。Phase 0-8b で確定）で既存プロセスのウィンドウを手前に出して終了する（応答がない場合も短くリトライして静かに終了し、DB を二重に開かない）。
- パソコンの起動時に動かす: `login_item.rs`（候補: `auto-launch`）。

### 9.6 エラー

- core は `Result<T, CoreError>`（thiserror）。app は anyhow。
- 利用者のデータで panic しない。core では `#![deny(clippy::unwrap_used, clippy::expect_used)]`。
- 失敗は状態バーに、わかる言葉で出します（§6.5）。

### 9.7 テスト

- core: service ごとに、§8.5 の不変条件のテストを書く。DB は `Connection::open_in_memory()`。「今日」「いま」は差し替えできる `Clock` で固定する。
- 必ず書くテスト:
  - 繰り返し（§8.7）: 月末（1/31 の毎月）、2月29日の毎年、2週間ごと、起点より前の曜日、`until_date`、休み。
  - 知らせ（§8.8）: 前の日の知らせ、1440分前、繰り返しの回ごとの知らせ、「10分後にもう一度」、開き直したときの `showing`、閉じているあいだの知らせ（24時間の境目）、日付を変えたら知らせが出直す。
  - 時刻の入力（§6.6）: 受け付ける書き方の全部と、受け付けない例。
- app: 画面の動きは、起動して目で確認します。Slint の MCP サーバー（`CLAUDE.md` 参照）が使えるときは、要素ツリーとアクセシビリティ情報、スクリーンショットで確認します。Slint のテスト用バックエンドで UI テストを書けるかは Phase 0 で調べます。

## 10. 品質の目標（非機能要件）

### 10.1 速さ（カード 5,000 枚、M1/M2 の Mac で）

- 起動してから操作できるまで 1 秒以内
- ふつうの操作（追加、チェック、移動）は 50ms 以内
- さがす は 100ms 以内
- 予定の「1か月」の表示（繰り返しの予定 100 件を含む）は 50ms 以内
- 30秒ごとの知らせの確認は 10ms 以内

### 10.2 データの安全

- 入力中にアプリを閉じても、閉じる直前の入力まで残る。
- 急に電源が切れても DB が壊れない（WAL）。
- 毎日のバックアップ（§8.10）。

### 10.3 動く環境

- macOS 13 以降（Apple Silicon を優先）
- Windows 10 / 11（x64）
- Linux は動けばよい（配布は P3）
- **ネットワークに接続しない**（利用状況の送信も、更新の確認もしない。祝日も同梱のデータを使う）

### 10.4 アクセシビリティの合格基準（全画面で確認）

- [ ] 文字のコントラスト比 4.5 以上（「はっきり」は 7 以上）。§7.2 の計算どおり。
- [ ] 押せる場所が 44 × 44 論理px 以上。
- [ ] フォーカスの枠（3px）が見える。キーボードだけで全部の操作ができる。
- [ ] 文字の大きさ「最大」・ウィンドウ最小サイズで、文字が切れたり重なったりしない。知らせの窓も同じ。
- [ ] 時間で消える表示、時間制限がない。
- [ ] 「動きを減らす」オンでアニメーションがない。
- [ ] 音を鳴らす設定オフのとき、音が一切出ない。
- [ ] ドラッグしなくても全部の操作ができる。
- [ ] 操作できる要素すべてに、読み上げ用の名前（`accessible-label`）と役割（`accessible-role`）がある。
- [ ] 日本語入力（変換中の表示、確定、Enter の扱い）が macOS と Windows で正しく動く。変換を確定する Enter でカードが追加されない。
- [ ] 知らせの窓が、ほかのアプリでの入力中にフォーカスを奪わない（macOS と Windows で確認）。
- [ ] 知らせの窓は、音なしで気づける大きさ・位置で、消すまで残る。
- [ ] 知らせの窓がメニューバー・Dock・タスクバーと重ならず、文字の大きさ「最大」で複数件あっても［全部わかった］が画面外に出ない。
- [ ] キーボードだけで知らせの全操作（メインのウィンドウ上部の「いま出ている知らせ」欄を含む）ができる。
- [ ] 土日・祝日・今日が、色だけでなく文字でわかる。

### 10.5 知らせの正確さ

- fuda が動いているとき、知らせは `fire_at` から 60 秒以内に出る。
- 同じ回の知らせが2回出ない（「10分後にもう一度」を除く）。
- 眠りから覚めたあと 60 秒以内に、閉じているあいだの知らせが出る。
- トレイでうしろで動いているあいだに fuda をもう一度起動しても、二重に起動せず既存ウィンドウが手前に出るだけで、知らせが重複しない。
